# Texts and languages

Two separate text sources:

| Texts | Owner | Where |
| --- | --- | --- |
| UI texts | frontend, vue-i18n | `frontend/src/locales/de.ts` (schema), `en.ts`, `fr.ts`, `es.ts`, `ru.ts` |
| API messages (errors and successes by message ID) | backend | `backend/src/messages/message-ids.ts`, `catalog.de.ts` … `catalog.ru.ts`, `GET /api/messages?lang=` |
| Block names and field names of the flow editor | HA | the editor catalog in the UI language (`GET /api/editor/catalog?lang=`) |
| "What's new" highlights | frontend | `frontend/src/constants/whatsNew.ts` (`LocalizedText` per item) |

## UI texts

- `de.ts` is the schema (`MessageSchema = typeof de`). Every other language must have the same keys.
  Fallback is `en`.
- Language: the user's choice (`settings.locale`, written only when the user picks one). Otherwise the
  first browser language the app has (`preferredLocale`), otherwise German.
- Plurals: en, fr, es use vue-i18n's own rule ("0 résultats"). Russian has its own rule
  (`i18n/pluralRules.ts`: 1 | 2–4 | 5+, with a zero form where en has one), so **ru has one plural form
  more than en**.
- Top-level keys follow the feature: `nav`, `list`, `detail`, `flow`, `helper`, `helperSettings`, `scene`,
  `areas`, `checkup`, `deps`, `history`, `ai`, `cleanup`, `toast`, `errors`, …

`locales/__tests__/keys.spec.ts` checks that every fixed `t("…")` key in the code exists in every
language, that fr / es have the placeholders and plural forms of en, and that ru plurals have one form
more. Dynamic keys (`` t(`detail.tabs.${tab}`) ``) are not found by the test. Check them by hand.

## API messages

- Every response carries `message` (an ID like `CATEGORY_NAME_TAKEN`) and `error`. Params go in
  `data.params` (docs/api.md).
- The `Catalog` type makes a missing text a build error in every catalog.
- The frontend loads the catalog for the UI language (`messagesStore.load` in `App.vue`) and shows errors
  with `messages.textFor(error, fallback)`, which fills `{placeholders}` from `params`.

## Recipes

- **New UI text:** add the key to `de.ts`, then the same key to `en`, `fr`, `es`, `ru` (ru plurals:
  one more form). Run `npm test` in `frontend/`.
- **New error from the backend:** an ID in `MESSAGE_ID`, a text in all five `catalog.*.ts`, and throw
  `apiError(MESSAGE_ID.x, { params })`. The UI needs no new key.
- **Release highlights:** see [../setup.md](../setup.md#releases). The test fails when the release
  version has no entry in `WHATS_NEW`.
